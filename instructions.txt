Inspira-Grid migration (repo-specific): CRA client/ -> Next.js 14 web/

Context
- This repo already contains a Next.js 14 app in web/ (App Router + TypeScript + Tailwind) and a Node/Express API in server/.
- The legacy CRA app lives in client/ and should be ported route-by-route into web/.

Do this first
1) Install deps and start both apps
   - npm run install-all
   - npm run dev (web: http://localhost:3000, API: http://localhost:5000)
2) Set environment for web/
   - Create web/.env.local and copy values from client/.env
   - Translate to NEXT_PUBLIC_* where needed (Firebase + API URL):
     - NEXT_PUBLIC_API_URL=http://localhost:5000
     - NEXT_PUBLIC_FIREBASE_API_KEY, NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN, NEXT_PUBLIC_FIREBASE_PROJECT_ID,
       NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET, NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID, NEXT_PUBLIC_FIREBASE_APP_ID
   - web/lib/firebase.ts and web/lib/api.ts already read from these variables

Routing: CRA -> Next App Router
- Create files under web/app to mirror routes. Examples:
  - /                -> web/app/page.tsx
  - /projects        -> web/app/projects/page.tsx
  - /projects/:id    -> web/app/projects/[id]/page.tsx
  - /dashboard       -> web/app/dashboard/page.tsx
  - /messages/:cid   -> web/app/messages/[conversationId]/page.tsx
  - /applications    -> web/app/applications/page.tsx
  - /auth/login      -> web/app/auth/login/page.tsx
- Replace react-router-dom Links with next/link; nav and footer come from web/app/layout.tsx
- Mark components that use hooks with "use client" at the top

Components and libs
- Move reusable components from client/src/components to web/components (e.g., ui/, auth/, projects/)
- Update imports to use tsconfig paths: @/components/*, @/lib/*, @/styles/*
- Convert .jsx to .tsx minimally; type props later if needed

API calls and auth
- Use web/lib/api.ts: api(path, init) builds JSON requests against NEXT_PUBLIC_API_URL and throws on non-OK
- For protected routes, include Firebase ID token headers:
  - const headers = await (await import("@/lib/authClient")).authHeaders()
- All Express endpoints are under http://localhost:5000/api/* and protected by validateFirebaseToken on the server

Styles and assets
- Tailwind is already configured in web/; prefer migrating styles to Tailwind
- If you must keep Bootstrap temporarily: npm --prefix web i bootstrap and import its CSS in web/app/layout.tsx
- Move files from client/public to web/public (same URLs)

Realtime (Socket.IO)
- Use socket.io-client from a Client Component and connect to the API origin from NEXT_PUBLIC_API_URL
- Join rooms as the server expects (user_, team_, conversation_) if your feature uses them

Verification
- Run npm run dev, navigate pages you ported, and watch server logs for CORS/auth issues
- Type-check on demand: npx tsc -p web --noEmit
- Lint web: npm --prefix web run lint

Decommission client/
- After parity, update docs, then remove client/ from active use

# InspiraGrid: Full Guide to Migrating from React to Next.js (Dark Theme, Student-focused)

This guide explains how to migrate your existing React project to Next.js without losing any features, while giving your website a modern dark theme suitable for students.

---

## 1. Install Next.js

1. Navigate to your React project:

   ```
   cd your-react-project
   ```

2. Install Next.js and required packages:

   ```
   npm install next react react-dom
   ```

3. Update `package.json` scripts:

   ```json
   "scripts": {
     "dev": "next dev",
     "build": "next build",
     "start": "next start"
   }
   ```

---

## 2. Restructure Project

Next.js uses **file-based routing**:

```
/pages
  index.js       -> Homepage
  _app.js        -> Global app wrapper
  anyPage.js     -> Other pages
/public           -> Static assets (images, fonts, favicon)
/components      -> All React components
/styles          -> CSS or SCSS files
/lib             -> Firebase or helper functions
```

Steps:

1. Move all React components to `/components`.
2. Move CSS/SCSS files to `/styles`.
3. Move images, logos, and static files to `/public`.

---

## 3. Setup `_app.js` for Global Styles and Context

Create `/pages/_app.js`:

```javascript
import '../styles/globals.css';

function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />;
}

export default MyApp;
```

* `globals.css` will contain your **dark theme styles**.

---

## 4. Convert `App.js` to `pages/index.js`

1. Move `App.js` content to `/pages/index.js`.
2. Update imports:

```javascript
import Navbar from '../components/Navbar';
import Footer from '../components/Footer';
import Hero from '../components/Hero';
```

3. Remove ReactDOM.render — Next.js handles this automatically.

---

## 5. Update Routing

Replace **React Router** with **Next.js routing**:

* Each file in `/pages` corresponds to a route.

  * Example: `pages/projects.js` → `/projects`
* Use Next.js `<Link>` for navigation:

```javascript
import Link from 'next/link';

<Link href="/projects">Projects</Link>
```

* Remove all `BrowserRouter`, `Routes`, `Route` from React Router.

---

## 6. Environment Variables

1. Create `.env.local`:

```
NEXT_PUBLIC_FIREBASE_API_KEY=your-api-key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-auth-domain
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-project-id
```

2. Use `NEXT_PUBLIC_` prefix for variables accessed in the browser.

---

## 7. Firebase Setup

* Move Firebase config to `/lib/firebase.js`:

```javascript
import { initializeApp } from "firebase/app";
import { getAuth } from "firebase/auth";

const firebaseConfig = {
  apiKey: process.env.NEXT_PUBLIC_FIREBASE_API_KEY,
  authDomain: process.env.NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN,
  projectId: process.env.NEXT_PUBLIC_FIREBASE_PROJECT_ID,
};

const app = initializeApp(firebaseConfig);
export const auth = getAuth(app);
export default app;
```

* Import `auth` in components as needed.

---

## 8. Dark Theme Setup

* In `/styles/globals.css`:

```css
:root {
  --bg-color: #121212;
  --text-color: #e0e0e0;
  --primary-color: #3b82f6;
  --secondary-color: #10b981;
  --accent-color: #f97316;
}

body {
  background-color: var(--bg-color);
  color: var(--text-color);
  font-family: 'Inter', sans-serif;
  margin: 0;
  padding: 0;
}

a {
  color: var(--primary-color);
  text-decoration: none;
}

button {
  background-color: var(--secondary-color);
  color: var(--text-color);
  border: none;
  padding: 0.5rem 1rem;
  cursor: pointer;
}
```

* Update component styles to use CSS variables for consistent dark theme.

---

## 9. API Routes (Optional)

Next.js supports serverless functions:

```
/pages/api/hello.js
```

```javascript
export default function handler(req, res) {
  res.status(200).json({ message: "Hello from Next.js API!" });
}
```

* Move any backend logic here if needed.

---

## 10. Images and Assets

* Use `/public` for static files.
* Use Next.js `<Image>` component for optimized loading:

```javascript
import Image from 'next/image';
import logo from '../public/logo.png';

<Image src={logo} alt="Logo" width={100} height={100} />
```

---

## 11. Testing

1. Run development server:

```
npm run dev
```

2. Check every page/component:

   * Firebase functionality
   * Navigation links
   * Forms, quizzes, dashboards
   * Dark theme consistency

3. Fix any broken imports or paths.

---

## 12. Deployment

* Next.js works best with **Vercel**:

  1. Connect GitHub repo
  2. Set environment variables in Vercel dashboard
  3. Deploy with `npm run build` and `npm run start`

---

## 13. Optional Enhancements for Students

* Use **cards, badges, progress bars** for engagement.
* Add **animations on hover** for buttons and links.
* Include **illustrations of students collaborating**.
* Keep UI **minimal, clear, and motivating** with dark theme.

---

## 14. Notes

* Keep components modular.
* Next.js supports **Server-Side Rendering (SSR)** if needed.
* Use **next/head** to manage page titles and metadata.
* Ensure Firebase authentication works after migration.
* Dark theme should be consistent across all pages.

---

**By following this guide, InspiraGrid will run on Next.js with a modern dark theme and all existing features intact.**
